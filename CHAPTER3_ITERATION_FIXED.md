          ## 3.5 DEVELOPMENT ITERATIONS

          The Rock Solid System was developed using an iterative and incremental approach following Agile methodology principles. The development process was divided into six (6) major iterations spanning twelve (12) weeks from February to April 2026. Each iteration involved close collaboration with Rock Solid Manpower Network and Consultancy Inc., incorporating client feedback and adviser guidance to ensure the system met both operational needs and academic standards.

          ## 3.5.1 ITERATION 1: REQUIREMENTS GATHERING AND INITIAL PLANNING

          **Duration:** Weeks 1-2 (February 1-14, 2026)

          ### Objectives

          The primary objective of the first iteration was to comprehensively understand the existing operations of Rock Solid Manpower Network and Consultancy Inc. and establish a detailed requirements specification that would guide all subsequent development activities. This foundation phase aimed to:
          - Document current business processes and pain points
          - Identify functional and non-functional requirements
          - Establish project scope and boundaries
          - Obtain stakeholder approval and commitment
          - Create initial system architecture plans

          ### Activities Performed

          **1. Initial Client Meeting (February 1, 2026)**
          The researchers conducted an extensive meeting with the client's management team, including the Operations Manager and three (3) selected staff members from the recruitment and deployment departments. The meeting lasted approximately four (4) hours and focused on:
          - Current recruitment workflow and challenges
          - Job order processing procedures
          - Document management practices
          - Deployment tracking methods
          - Reporting requirements and frequency

          **2. Requirements Gathering Phase (February 1-7, 2026)**
          Through structured interviews and direct observation over five (5) working days, the researchers documented:
          - **Current Challenges Identified:**
            - Paper-based applicant records causing retrieval delays (average 10-15 minutes per search)
            - Scattered document storage across multiple filing cabinets
            - Manual tracking of applicant status leading to oversight
            - Difficulty generating management reports
            - Lack of backup for critical information
            - Time-consuming job matching process

          - **Functional Requirements Documented:**
            - User authentication with role-based access (Admin and Staff)
            - Applicant information management (add, view, edit, delete)
            - Job order creation and tracking
            - Applicant-to-job matching functionality
            - Employee records management (201 files)
            - Attendance tracking and recording
            - Payroll computation based on attendance
            - Document upload and storage
            - Comprehensive reporting module
            - Deployment monitoring and tracking

          - **Non-Functional Requirements Identified:**
            - System must be web-based for accessibility
            - Response time under 2 seconds for data retrieval
            - Secure data storage with encryption
            - User-friendly interface requiring minimal training
            - Mobile-responsive design
            - Data backup and recovery capabilities
            - Support for concurrent users (minimum 10)

          **3. Technical Feasibility Analysis (February 5-8, 2026)**
          The researchers evaluated various technology options and selected:
          - **Frontend:** Next.js 16.1.6 with React 19 and TypeScript
            - Rationale: Server-side rendering for better performance
          - **Backend:** Supabase (Backend-as-a-Service)
            - Rationale: Built-in authentication, real-time database, and file storage
          - **Database:** PostgreSQL via Supabase
            - Rationale: Reliable, scalable, supports complex relationships
          - **Styling:** Tailwind CSS
            - Rationale: Rapid development with consistent design

          **4. Adviser Consultation (February 10, 2026)**
          A comprehensive consultation with the project adviser was conducted to:
          - Align system scope with study objectives
          - Validate methodology approach
          - Confirm academic rigor of requirements gathering
          - Obtain approval for technology selections
          - Establish evaluation criteria for the study

          **5. Requirements Documentation (February 8-14, 2026)**
          Created comprehensive requirements specification document including:
          - System overview and objectives

          - Data flow diagrams
          - Initial database schema design
          - Interface mockups and wireframes

          ### Challenges Encountered

          **1. Scope Creep Management**
          - **Problem:** Client initially requested extensive features including SMS notifications, email automation, and mobile app, which exceeded the study timeline and resources
          - **Impact:** Risk of project delay and inability to complete within academic timeframe
          - **Solution:** Employed MoSCoW prioritization method (Must have, Should have, Could have, Won't have) to categorize features. Agreed with client to focus on core functionality for initial release, with additional features as future enhancements

          **2. Process Ambiguity**
          - **Problem:** Different staff members described varying procedures for the same processes, particularly in applicant status tracking and job matching
          - **Impact:** Unclear system specifications and potential for incorrect implementation
          - **Solution:** Conducted additional follow-up interviews, observed actual workflows, and created process flowcharts for client validation. Established standard operating procedures to be implemented in the system

          **3. Technical Knowledge Gap**
          - **Problem:** Client staff had limited experience with modern web-based systems, expressing concerns about system complexity and adoption
          - **Impact:** Potential resistance to system implementation and lower usage rates
          - **Solution:** Committed to designing an intuitive, user-friendly interface with comprehensive training program. Scheduled regular demonstrations throughout development to familiarize users with the system progressively

          **4. Data Migration Concerns**
          - **Problem:** Existing records in paper format (approximately 500+ applicant files) needed to be digitized
          - **Impact:** Significant time investment for data entry and potential for transcription errors
          - **Solution:** Planned phased data migration strategy: critical active records first, then historical records. Implemented data validation rules to ensure accuracy during migration

            - Built in buffer time for testing and refinement
            - Established milestones and deliverable dates

          **1. Middleware Redirect Loop**
          - **Problem:** Initial middleware implementation caused infinite redirect loops where users continuously bounced between login page and dashboard
          - **Root Cause:** Middleware was checking authentication on all requests including static files and API calls, causing circular dependencies
          - **Impact:** System completely unusable, could not access any page
          - **Solution:** Implemented file extension regex to allow public files, added specific path checks for login and dashboard routes, created clear conditional logic separating authenticated and unauthenticated flows

          **2. Role Permission Complexity**
          - **Problem:** Determining appropriate permission boundaries between Admin and Staff roles proved more complex than anticipated
          - **Client Feedback:** Initial design too restrictive for staff, hindering daily operations
          - **Impact:** Potential for poor user adoption if staff felt limited
          - **Solution:** Conducted additional meeting with client (February 21, 2026) to refine permission matrix. Increased staff permissions for viewing records while maintaining delete restrictions for data integrity

          **3. Session Management Issues**
          - **Problem:** Users reported being logged out unexpectedly during active use
          - **Technical Cause:** Session refresh token not properly implemented
          - **Impact:** Interrupted workflows and user frustration
          - **Solution:** Implemented automatic session refresh before expiration using Supabase's built-in refresh mechanism, extending sessions during active use

          **4. Mobile Responsiveness**
          - **Problem:** Login page and sidebar navigation displayed poorly on mobile devices
          - **Observation:** Form fields too small, sidebar overlapped content
          - **Impact:** Poor mobile experience contrary to requirements
          - **Solution:** Implemented responsive design using Tailwind's mobile-first approach, created collapsible sidebar for mobile screens, increased touch target sizes to minimum 44px

          ### Challenges Encountered

          **1. Form Complexity and User Experience**
          - **Problem:** 60+ field form overwhelming for users, easy to miss required fields or make errors
          - **Client Feedback:** Staff concerned about time to complete each entry
          - **Initial Implementation:** Single long scrolling form
          - **Impact:** Potential for incomplete data, user fatigue, data entry errors
          - **Solution:** Organized fields into 11 logical sections with visual separators, implemented progressive disclosure for optional sections, highlighted required fields with asterisks and color coding, added field-level help text for complex fields, considered multi-step form (decided to keep single page for now but noted for future enhancement)

          **2. File Upload Performance**
          - **Problem:** Large file uploads (documents, scanned IDs) took too long without feedback
          - **Symptoms:** Users unsure if upload working, clicked multiple times causing duplicates
          - **Technical Issue:** No progress indicator implemented initially
          - **Impact:** Poor user experience, duplicate uploads, support requests
          - **Solution:** Implemented progress bar showing upload percentage, added file name display during upload, showed estimated time remaining, implemented duplicate file detection, added file compression for images before upload (reduces size by ~40%)

          **3. Search Performance Degradation**
          - **Problem:** Real-time search became laggy with 500+ records
          - **Symptoms:** 1-2 second delay after each keystroke, UI felt sluggish
          - **Root Cause:** Re-filtering entire dataset on every character input without optimization
          - **Impact:** Poor user experience, perceived as system being slow
          - **Solution:** Implemented React useMemo hook for memoized filtering (only recalculates when dependencies change), added input debouncing (waits 300ms after last keystroke), optimized filter algorithm complexity, result: Search now instant even with 1000+ records

          **4. Status Update Workflow Ambiguity**
          - **Problem:** Client initially unclear about exact status progression and who can update status
          - **Confusion:** Should staff be able to mark as "Deployed"? What triggers "For Deployment"?
          - **Impact:** Risk of implementing incorrect business logic
          - **Solution:** Conducted additional workflow clarification session (March 8, 2026), created status transition diagram for approval, defined that staff can update any status except "Blacklisted" (admin only), documented status meanings and typical progression, implemented status change logging (who changed, when, from/to)

          **5. Data Entry Time Concerns**
          - **Problem:** Staff concerned about 8 minutes per applicant entry time (currently 500+ applicants to digitize)
          - **Calculation:** 500 applicants × 8 minutes = 4000 minutes = 66 hours of data entry
          - **Impact:** Resource strain, potential resistance to system adoption
          - **Solution:** Proposed phased data migration: Phase 1: Active applicants (current candidates) - ~100 records, Phase 2: Recent applicants (last 6 months) - ~150 records, Phase 3: Historical records (older) - ~250 records, offered to assist with initial data migration, implemented bulk import consideration for future enhancement
